# اللَّبنة للبناء والإعمار — ALLABINA

منصة تونسية لتسجيل مطالب السكن وتنقيط الحرفاء وربطهم بحلول البناء والتمويل.
النسخة التجريبية — الولاية الأولى: **صفاقس**.

## التشغيل

```bash
npm run dev
```

الموقع على <http://localhost:3100>.

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | تشغيل نسخة التطوير على المنفذ 3100 |
| `npm run build` | بناء نسخة الإنتاج |
| `npm start` | تشغيل نسخة الإنتاج |
| `npm run migrate` | تطبيق ملفّات `supabase/migrations/` على قاعدة البيانات |
| `npm test` | تشغيل الاختبارات (Vitest) |
| `npm run test:watch` | الاختبارات في وضع المتابعة |

> ⚠️ لا تشغّل `npm run build` وخادم التطوير يخدم في نفس الوقت: الاثنان يكتبان في `.next`
> ويتضاربان. أوقف `npm run dev` أوّلاً، وبعد البناء امسح `.next` قبل العودة للتطوير.

## النفاذ إلى لوحة القيادة

المصادقة عبر **Supabase Auth** (بريد + كلمة سرّ)، والجلسة في كوكي httpOnly يجدّدها
`middleware.ts`. لا توجد كلمة سرّ مشتركة.

| الدور | المطالب | تعديلها | تصدير CSV | المعطيات المرجعية | الفريق |
|---|---|---|---|---|---|
| مالك | ✓ | ✓ | ✓ | ✓ | ✓ ومع المدراء |
| مدير | ✓ | ✓ | ✓ | ✓ | الوكلاء والمطّلعون |
| وكيل | ✓ | ✓ | — | — | — |
| مطّلع | ✓ | — | — | — | — |

إنشاء حساب المالك الأوّل (كلمة السرّ تُطلب تفاعلياً ولا تظهر):

```bash
node scripts/create-owner.mjs allabina@gmail.com
```

بقيّة الأعضاء يُضافون من `/admin/team` بكلمة سرّ مؤقّتة يغيّرها العضو عند أوّل دخول.
كلّ دخول أو تغيير دور أو ضبط كلمة سرّ يُسجَّل في جدول `staff_events`.

## قواعد لا يُحاد عنها

1. **المتصفّح لا يكتب في قاعدة البيانات.** كلّ إدراج يمرّ عبر Server Action في الخادم، وهو
   الذي يتحقّق ويحسب التنقيط. RLS مفعّل على كلّ الجداول، ودور `anon` يقرا الولايات
   والمعتمديات فقط.
2. **المفتاح `SUPABASE_SECRET_KEY` في الخادم فقط.** ممنوع في أيّ متغيّر يبدأ بـ `NEXT_PUBLIC_`.
3. **`.env` لا يُنشر ولا يُلصق في أيّ محادثة.**
4. **الـDevis مجمَّد وقت توليده وصالح 30 يوماً.** المدّة في `app_settings`
   (`devis.validity_days`)؛ كلّ سطر ينسخ السعر والكمّية والوحدة؛ تغيير سعر في
   البوردرو يطبَّق على العروض الجديدة وحدها. صيغ الكمّيات تُقيَّم بمقيّم خاصّ لا بـ`eval`.
5. **لا نشر لحالة حريف بلا موافقته.** `case_studies.published` محروس بقيد في قاعدة
   البيانات: النشر مستحيل ما دام `consent_given = false`، مهما جاء من الواجهة.
6. **العروض العقارية لا تُنشر آلياً.** كلّ عرض يدخل بحالة `pending`؛ المطابقة تشمل
   العروض `approved` وحدها. المحرّك يقترح ويفسّر — لا يقرّر ولا يُعلم الحريف بشيء تلقائياً.
7. **ما يراه الحريف منفصل عن الملاحظات الداخلية.** `public_update` و`public_next_step`
   يكتبهما الفريق عمداً في `/admin/[id]`؛ `request_interactions` و`next_action` داخلية
   ولا تُعرض أبداً في `/suivi`. صفحة المتابعة لا ترجع اسماً ولا هاتفاً ولا مبلغاً.
8. **كلّ رقم يمرّ عبر `lib/format.ts`.** الفاصل بين الآلاف فراغ ضيّق غير فاصل (`U+202F`)
   لا فراغ عادي: الفراغ العادي محايد في خوارزمية الاتجاه فيقطع «91 733» ويقلبها «733 91»
   داخل نصّ عربي. المجالات (`1 200 – 1 350`) تُلفّ في `<bdi dir="ltr">`، والمبالغ في `<bdi>`
   وحدها حتى تبقى العملة في مكانها الطبيعي حسب اللغة. يحمي هذه القاعدة `tests/format.test.ts`.

## الفهرسة (SEO)

- `robots.txt` و`sitemap.xml` يتولّدان تلقائياً (`app/robots.ts` · `app/sitemap.ts`)،
  والـback-office مستثنى من الفهرسة.
- كلّ صفحة تحمل `canonical` و`hreflang` للغتين، و`og:` خاصّة بكلّ لغة.
- العنوان الأساسي يُقرأ من `NEXT_PUBLIC_SITE_URL`؛ عند غيابه يرجع لـ`localhost`.
  **لازم ضبطه عند النشر** وإلّا بقيت الروابط في الخريطة تشير إلى localhost.

## النشر

الإنتاج على Vercel (المشروع `app1`، الموقع www.allabina.site). **الدفع إلى GitHub وحده لا ينشر** ما دام
المشروع غير مربوط بالمستودع؛ الطريق الوحيد هو سكربت النشر، وفيه صمّامات الأمان كلّها:

```bash
npm run release            # ينشر HEAD إلى الإنتاج
npm run release:preview    # رابط معاينة مؤقّت، لا يمسّ الموقع
npm run rollback           # يرجع إلى الدبّوس السابق (أو: npm run rollback -- prod/2026-09-09-2015)
npm run release -- --status
```

ما يفعله `release` بالترتيب، ويتوقّف عند أوّل فشل دون أن يمسّ الموقع:

1. يرفض إلّا من `main` ومن التزام موجود على GitHub — لا شفرة محلّية غير مدفوعة.
2. يصدّر **شجرة الالتزام** إلى مجلّد مؤقّت ويعمل عليها، لا على مجلّد العمل (عمل جلسة أخرى نصف منتهٍ لا يتسرّب).
3. يمرّر `tsc` والاختبارات على تلك الشجرة.
4. يرفع الأرشيف إلى Vercel (`.vercelignore` يمنع `.env` وملفّات العمل).
5. اختبار دخاني على الموقع الحيّ؛ إن فشل **يرجع تلقائياً** إلى الدبّوس السابق.
6. يدقّ **دبّوساً**: وسم `prod/<تاريخ>` على الالتزام برابط النشر، يُدفع إلى GitHub. كلّ ما كان حيّاً يوماً له مسمار.

قبل ذلك كلّه، خطّاف `pre-push` (يُفعَّل بـ `npm install`) يفحص كلّ التزام يُدفع بالطريقة نفسها، وGitHub Actions
يعيد `tsc` والاختبارات على كلّ دفعة. للطوارئ فقط: `SKIP_TREE_CHECK=1 git push`.

يحتاج السكربت جلسة `vercel login` على الجهاز (أو `VERCEL_TOKEN` في `.env` — لا يُلصق مفتاح في محادثة أبداً).

المتغيّرات المطلوبة في بيئة الإنتاج (Vercel → Settings → Environment Variables):

| المتغيّر | ملاحظة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | عامّة، تصل المتصفّح |
| `SUPABASE_URL` · `SUPABASE_SECRET_KEY` | **خادم فقط** — لا يُوضع في متغيّر `NEXT_PUBLIC_` |
| `NEXT_PUBLIC_SITE_URL` | `https://www.allabina.site` |
| `WINSMS_API_KEY` · `WINSMS_SENDER` | بدونهما لا تُرسل أيّ رسالة قصيرة (يفشل بهدوء) |
| `SMS_ENABLED` | اتركه غير معرَّف في الإنتاج؛ `false` يغلق الإرسال كلّياً |
| `DATABASE_PASSWORD` | للـmigrations فقط، ليس للتطبيق |

## نقاط تحتاج قراراً قبل الإطلاق

- **الفرضيات البنكية**: المنصة لا تثبّت أيّ نسبة. المحاكي يشتغل بفرضيات يضبطها المستعمل،
  والتنقيط يستعمل فرضيات داخلية للترتيب فقط (`scoring.assumed_*` في `app_settings`).
  النصّ المعروض تحت كلّ نتيجة في `finance.terms_note`.
- **صيغ التمويل** (`financing_products`): مسجّلة صيغتان لبنك الزيتونة في طور التثبّت. عند
  التثبّت الرسمي: املأ `verified_at` ليختفي الوسم.
- **العمادات** (`imadas`): فارغة. تُلصق من قائمة وزارة الداخلية في `/admin/reference`.
- **أسعار البناء** (`price_references` · `product = construction`): معبّأة بثلاث فئات HT
  (عادي 1 200–1 350 · متوسّط 1 400–1 600 · Haut Standing 1 700–2 000)، بمرجع 1 600 د/م² HT.
- **أسعار الأرض والشقق** (`price_references`): مازالت فارغة، تُعبّأ لصفاقس.
- **الأداءات**: كل الأسعار HT. عند إدخال `finance.vat_pct` يمكن عرض TTC إلى جانب HT.
- **معتمديات صفاقس**: 16 معتمدية حسب تقسيم وزارة الداخلية (`0002_seed_sfax.sql`).
- **لوحة القيادة**: محميّة حالياً بكلمة سرّ واحدة. قبل التوسّع تُعوَّض بـ Supabase Auth
  وجدول `staff` (موجود في المخطّط).
- **سياسة الخصوصية** (`/confidentialite`): نصّ أوّلي يحتاج مراجعة قانونية.
